    Conversation design
    
  
    Every call walks the same state machine whether the rules engine or Claude is driving. The brain decides the words; the state machine decides what is allowed. That split is what keeps a regulated call safe to automate.
    
  
    

    stateDiagram-v2
    [*] --> Greet
    Greet --> Verify: agent discloses identity and purpose
    Verify --> Disclose: borrower confirms
    Verify --> WrongParty: borrower denies / not available
    WrongParty --> [*]: no loan details shared
    Disclose --> Intent: EMI amount and due date stated
    Intent --> PTP: "will pay" (date captured)
    Intent --> Extension: "need time"
    Intent --> Dispute: "already paid" / "wrong amount"
    Intent --> Distress: job loss, illness, bereavement
    Intent --> Complaint: "stop calling me"
    Intent --> Intent: unclear (max 2 reprompts)
    Intent --> Handoff: still unclear
    PTP --> Close
    Extension --> Close: offer callback, no waiver promised
    Dispute --> Handoff
    Distress --> Handoff
    Complaint --> Handoff: opt-out noted
    Handoff --> [*]: human agent, warm transfer note
    Close --> [*]: grievance channel stated

    
  
    

    


    
  
    
    
    
      
    Guardrails
    
      
    Hard rules enforced in code, not just in the prompt.
    
      
      
        
    1. Identify first. The agent names itself as an automated assistant from the lender in the first sentence. No loan detail is spoken before identity is confirmed.
      2. 
        
    2. Never promise a waiver. Requests for interest or penalty waivers are acknowledged and routed to a human. The agent has no vocabulary for "waived".
      3. 
        
    3. Never threaten. Words implying legal action, visits, or consequences are blocked at the output layer. If the brain produces one, the line is replaced and logged.
      4. 
        
    4. Distress ends automation. Mentions of job loss, hospitalisation, death in the family or self-harm trigger an immediate, empathetic handoff. No payment ask follows.
      5. 
        
    5. "Stop calling" means stop. A do-not-call request or a harassment complaint ends the automated call at once, with an apology and a handoff to record the preference. No payment ask follows.
      6. 
        
    6. Two reprompts, then a human. If intent is still unclear after two tries, the agent stops guessing.
      7. 
        
    7. Always close with the grievance channel. Every completed call states how to raise a complaint, as RBI's Fair Practices Code expects.

    Why these choices
    
      
    
        
    Browser STT/TTS first
    The Web Speech API ships in Chrome with hi-IN and en-IN voices, which makes the demo zero-dependency. In production this swaps for a streaming ASR tuned on Indian code-mixed speech and a lower-latency TTS; the state machine does not change.
    
        
    Two brains, one contract
    The rules engine is deterministic and auditable, so compliance can sign off on every path. Claude handles phrasing and messier intents. Both must return the same JSON: next state, reply, extracted date, flags.
    
        
    Analytics is the second product
    The post-call scorer is the same logic a QA team runs on human agents. Automating the call and auditing the call share one schema, so analytics works on human calls too.
    
        
    Latency is a feature
    Each turn shows STT, decision and reply-start times. Above roughly 800 ms end to end, people talk over the agent; that budget drives every vendor choice.
    
      
    
    
    
  
    

    


    
  
    Eval set
    
  
    Scripted borrower replies with the expected outcome. Run them against the rules engine to see which paths hold. This is the regression suite a PM would extend every time a real call surfaces a new phrasing.
